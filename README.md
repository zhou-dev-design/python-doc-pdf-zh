# old —— 历史版本归档

这个分支**不是代码**，只放已经被新版本顶下来的 PDF 产物。

## 为什么有这个分支

产物平时在 **Releases**，每条版本线只保留**最新补丁版**那一个 release。
补丁版升级时（如 3.15.2 → 3.15.3），旧 release 的附件会被搬到这里、然后删掉原
release —— 于是 Releases 不会无限堆积，而历史版本也没丢。

归档由 CI 自动完成（`archive-eol` job 处理 EOL 版本，发布步骤处理被顶下来的
补丁版）。**不要手工往这里加文件**，下次自动归档可能冲突。

## 目录结构

```
old/
├── v3.10.22/                                 ← 每个 tag 一个目录
│   ├── Python-3.10.22-docs-20261103.pdf      合并册（单本，直接看）
│   └── Python-3.10.22-docs-20261103.rar      全部分册 + 验收报告（包内中文原名）
└── …
```

目录名就是当时的 release tag，里面的文件与该 release 的附件**完全相同**。

## 怎么下载

```bash
# 整份
git clone --depth 1 --branch old https://github.com/<owner>/<repo>.git

# 单个文件
curl -LO "https://raw.githubusercontent.com/<owner>/<repo>/old/v3.10.22/<文件名>"
```

## 两个注意点

- **这里的内容是冻结的**：不会随上游更新重新编译。要最新版请去 Releases。
- **分支会越来越大**：每归档一个补丁版约 +120 MB，git 不会自动瘦身。
  嫌大可以删掉对应目录后提交，或整个分支重建（归档内容在需要时可以从上游重新构建）。
